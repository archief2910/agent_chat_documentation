Creates a chat when `chatId` is omitted, saves the user message, and starts one durable run. The HTTP call returns `202` while the run is still `queued`.

This route does not accept attachments. To attach files, use [Submit a message](/messages).

<ParamField body="text" type="string" required>
  1 to 32,000 characters on the current deployment. `GET /api/v1/config` reports `maxMessageChars`.
</ParamField>

<ParamField body="chatId" type="string">
  Existing chat. Omit it and the API creates one.
</ParamField>

<ParamField body="clientMessageId" type="string">
  UUID. Optional here. If you omit it, the server generates one. Sending the same value again returns the original run.
</ParamField>

<ParamField body="planMode" type="boolean">
  When true, billable Magica tools wait for approval before they run.
</ParamField>

<RequestExample>

```bash
curl -X POST https://agent-chat-backend-production.up.railway.app/api/v1/chat/completions \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"text":"Crop the left half of the image.","clientMessageId":"6f1c9a4e-6b3a-4d5e-9f21-0c2a9b7d4e11"}'
```

</RequestExample>

<ResponseExample>

```json
{
  "chatId": "chat_123",
  "messageId": "msg_user",
  "assistantMessageId": "msg_assistant",
  "runId": "run_123",
  "status": "queued",
  "replayed": false,
  "realtime": {
    "token": "pk_...",
    "triggerRunId": "run_trigger",
    "streamId": "agent-output"
  }
}
```

</ResponseExample>

<ResponseField name="runId" type="string" required>
  Poll this with `GET /api/v1/runs/{runId}`.
</ResponseField>

<ResponseField name="status" type="string" required>
  `queued` in this response. Later values are `thinking`, `working`, `waiting`, `stopping`, then `completed`, `failed`, or `cancelled`.
</ResponseField>

<ResponseField name="realtime.streamId" type="string" required>
  Always `agent-output`. Text chunks use this stream. Run status uses metadata on the same Trigger.dev run.
</ResponseField>

## Read history

- `GET /api/v1/chats?cursor=&limit=&q=` lists chats. Pinned chats stay on their own list. `q` matches pinned chats by title. Unpinned chats match the title or the message text.
- `GET /api/v1/chats/{chatId}` reads one chat.
- `GET /api/v1/chats/{chatId}/messages?cursor=&limit=` returns the newest page first. `nextCursor` asks for older messages.
- `PATCH /api/v1/chats/{chatId}` accepts `title` (1 to 120 characters) and `pinned`.
- `POST /api/v1/chats/{chatId}/duplicate` copies the chat for its owner.
- `DELETE /api/v1/chats/{chatId}` removes the chat for its owner only.
