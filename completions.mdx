## Start a turn

`POST /api/v1/chat/completions`

```json
{
  "chatId": "optional existing chat",
  "text": "Crop the left half of the attached image.",
  "clientMessageId": "6f1c9a4e-6b3a-4d5e-9f21-0c2a9b7d4e11",
  "planMode": false
}
```

Omit `chatId` to create a chat. `clientMessageId` is optional on this route. If you omit it, the server generates one. Send the same `clientMessageId` again to get the original run instead of a second one. This route does not accept attachments.

`202` response:

```json
{
  "chatId": "chat_123",
  "messageId": "msg_user",
  "assistantMessageId": "msg_assistant",
  "runId": "run_123",
  "status": "queued",
  "replayed": false,
  "realtime": {
    "token": "pk_...",
    "triggerRunId": "run_trigger",
    "streamId": "agent-output"
  }
}
```

`POST /api/v1/chats/{chatId}/messages` is the route the chat UI uses. `clientMessageId` is required. Attachments are optional, at most 8, with unique positions:

```json
{
  "text": "Crop the left half.",
  "clientMessageId": "6f1c9a4e-6b3a-4d5e-9f21-0c2a9b7d4e11",
  "planMode": false,
  "attachments": [{ "assetId": "asset_123", "position": 0 }]
}
```

`text` is 1 to 100,000 characters after trimming.

## Read

- `GET /api/v1/chats?cursor=&limit=&q=` returns pinned chats separately from the cursor page, so pinning a chat does not shift the cursor.
- `PATCH /api/v1/chats/{chatId}` accepts `{ "title" }` (1 to 120 characters) and `{ "pinned": true }`.
- `POST /api/v1/chats/{chatId}/duplicate` copies the chat for its owner.
- `GET /api/v1/chats/{chatId}/messages?cursor=&limit=` returns the newest page first. `nextCursor` asks for older messages.
- `q` matches pinned chats by title. Unpinned chats match the title or the message text.

`DELETE /api/v1/chats/{chatId}` removes the chat for its owner only.
