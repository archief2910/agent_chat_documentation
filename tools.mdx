Direct tool execution. The response is `202`. The same `clientRequestId` returns the existing run.

<ParamField path="name" type="string" required>
  `crop_image`, `gpt_image_2`, or `merge_videos`.
</ParamField>

<ParamField body="clientRequestId" type="string" required>
  UUID. A repeat of the same id does not start a second provider run.
</ParamField>

<ParamField body="input" type="object" required>
  Tool fields. See the three shapes below.
</ParamField>

<RequestExample>

```bash
curl -X POST https://agent-chat-backend-production.up.railway.app/api/v1/tools/crop_image/runs \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"clientRequestId":"3b1c5d7e-1111-4222-8333-444455556666","input":{"image_url":"https://cdn.example/photo.png","x_percent":0,"y_percent":0,"width_percent":50,"height_percent":100}}'
```

</RequestExample>

<ResponseExample>

```json
{
  "runId": "toolrun_123",
  "status": "queued"
}
```

</ResponseExample>

`GET /api/v1/tools/runs/{runId}` returns `status`, `externalRunId`, `output`, `chargedMicrocredits`, and `errorMessage`.

`GET /api/v1/tools` lists the same registry the model sees.

## Inputs

- Crop Image takes `image_url` and one complete rectangle: all four percent fields, pixel width and height, or `crop` with `x`, `y`, `width`, and `height`.
- GPT Image 2 uses the text sub-model unless `uploadedImages` is present, which selects the edit sub-model. Every other field is checked against Magica's current schema.
- Merge Videos takes `video_urls` in playback order, from 2 to 100, and `transition` of `none`, `fade`, or `dissolve`.

Inside a conversation the model chooses the tool. The server calls `POST /v1/nodes/{nodeType}/run` on Magica, saves `runId`, then polls `GET /v1/nodes/runs/{runId}`. A retry reuses that id. Result URLs are stored as generated assets. The Magica key is not in the response.
