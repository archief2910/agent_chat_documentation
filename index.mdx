Base URL: `https://agent-chat-backend-production.up.railway.app`

Every versioned route is under `/api/v1`. Send `Authorization: Bearer <credential>` on those routes. `GET /api/health` and `GET /api/v1/config` are open.

<Check>
  Checked against the deployment on 13 Oct 2026. `GET /api/health` returned `200` with `{ "ok": true, "database": "up" }`.
</Check>

`GET /api/v1/config` on that host currently reports:

| Field | Live value |
| --- | --- |
| `model` | `openrouter/free` |
| `maxMessageChars` | `32000` |
| `admissionMicrocredits` | `5000` (0.005 credits) |
| `uploads.enabled` | `true` |

| `uploads.maxFileBytes` | `500000000` |
| `uploads.monthlyBytes` | `5000000000` |
| `waitpointTimeoutMinutes` | `30` |

A message does not wait for the model to finish.

<Steps>
  <Step title="Start the turn">
    `POST /api/v1/chat/completions` creates a chat when you omit `chatId`. `POST /api/v1/chats/{chatId}/messages` sends into a chat you already have. Both return `202` with `runId` and status `queued`.
  </Step>
  <Step title="Read the run">
    Poll `GET /api/v1/runs/{runId}` until `status` is `completed`, `failed`, or `cancelled`. `progress` is `100` only then.
  </Step>
  <Step title="Reload from Postgres">
    Text streams on stream id `agent-output`. Status, tools, and waitpoints travel as run metadata. PostgreSQL is the copy a reload reads.
  </Step>
</Steps>

A chat can have one active run. A second send returns `409` with code `RUN_ACTIVE` and that run's id.

Without a credential, those routes return `401`:

```json
{
  "error": {
    "code": "UNAUTHENTICATED",
    "message": "Sign in to continue.",
    "retryable": false,
    "traceId": "687ac8e0-ca57-4af8-9ca7-7085acafd1e2"
  }
}
```

`traceId` matches the `x-request-id` response header.

Crop Image, GPT Image 2, and Merge Videos run on Magica through `POST /api/v1/tools/{name}/runs`. The Magica key stays on the server.
